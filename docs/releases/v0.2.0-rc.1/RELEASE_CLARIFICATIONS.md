# Qualification update for SortSize 0.2.0-rc.1

This document accompanies the public containers for frozen product source `448e92e572c0e986f7706d2373531e033196ed1d`. They reuse the qualified executable bytes without recompilation. Four historical source documents have personal build prefixes removed; their public renditions and the refreshed manifests are disclosed in PUBLIC_DISTRIBUTION.json. Original private evidence and original qualified containers are preserved separately. The archive hashes below identify the original qualification containers; the current public-container hashes are in the accompanying SHA256SUMS and PROVENANCE.json. These immutable archives retain their packaging-time statements from 21 October 2026. The public prerelease and current downloads are available in [SortSize-OSS](https://github.com/tazmen3/SortSize-OSS/releases/tag/v0.2.0-rc.1).

1. **Clean Windows validation:** the Windows README introduction says validation on a clean system is not yet demonstrated, and `BUILDINFO.json` records `clean_windows_validation: "not performed"`. Those statements reflect packaging-time status. Later qualification successfully exercised the final ZIP on a separate clean Windows 11 VM, without Rust/Visual Studio, under a standard account. Final ZIP SHA-256: `16786e373a3945a18e36196863a69c63e9be7d9e388d512943e4b84ed750daf7`. The first preflight used an earlier archive; it establishes the initial environment, not the identity of the final ZIP. The final-archive hash and executed-binary hashes establish the final package identity.
2. **Clean Ubuntu validation:** the Linux build metadata points to historical v0.1 validation. The final Linux archive was subsequently tested in an isolated Ubuntu 24.04.5 container, without compiler tools, network or mounted host libraries. Final archive SHA-256: `016ec6e82b5588375267f5c03e01a77c4e8d41d772b5e8c1a49d4f2bb3570fb5`.
3. **Windows display scaling:** the earlier 1280×800 VM overflow and forced 150%/200% tests remain historical observations. Later tests measured native 96/120/144/192 DPI on 2560×1600 and exercised the main window and About/Licenses. This does not certify multiple monitors or make an undersized screen sufficient. At 125%, 750 px client height + 47 px frame = 797 px, 57 px above the earlier 740 px work area.
4. **Microsoft runtime:** 14.44.35211.0 is the successful clean-VM test configuration, not a proven minimum. The tools directory label alone does not identify the compiler/linker patch version: a current inspection of the development environment found directory 14.44.35207 but product version 14.44.35229. This inspection is not a retrospective build-time fingerprint. For deployment use the latest official supported x64 v14 package, at least as recent as the MSVC Build Tools, as Microsoft recommends. No runtime DLL or Microsoft installer is included. A clean-VM test with that newer deployment runtime is not claimed here.
5. **CLI names:** generic source-build examples use `sortsize`. The distributed executables are `./sortsize-cli` on Linux and `.\sortsize-cli.exe` in Windows PowerShell.
6. **Historical tooling:** `scripts/verify_v01_integration.py` retains a v0.1-specific top-level lockfile check; its top-level command is not a v0.2 acceptance test. The release-archive verification function and the final review's separate verifier check the frozen RC archives against their exact source. Use the supplied `rebuild-linux.sh` / `rebuild-windows.ps1` for offline source reconstruction, with the documented external toolchain prerequisites.

These updates establish the tested scope; the limitations in the release notes and bundled reservations remain applicable. None of these documents claims complete legal, platform, accessibility or performance certification.
